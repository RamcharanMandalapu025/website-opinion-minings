# Website Evaluation Using Opinion Mining

Aspect-based sentiment analysis (ABSA) for e-commerce website comments. Users submit comments;
the system detects which **aspects** are mentioned, scores the **sentiment of each aspect**,
filters spam, and shows per-website star ratings with a confidence indicator and an overall
trust score.

```
Input : "Product was original but delivery took 12 days and support never replied."
Output: Genuineness = Positive | Delivery = Negative | Support = Negative
```

Aspects: genuineness, delivery time, product quality, customer support, refund/return, pricing.

## Architecture

```
raw comment
   │
   ▼
spam filter (TF-IDF + LogReg + style cues + duplicate check) ── spam ──► stored, weight 0
   │ clean / suspicious
   ▼
preprocessing: clean text → split into clauses
   │
   ▼
aspect detection   V1 keyword lexicon │ V2 trained multi-label classifier (+ keyword features)
   │
   ▼
sentiment per clause   VADER + domain lexicon + phrase rules │ Transformer (DistilBERT) + rules
   │                   + sarcasm layer (flips positive-opener + negative-event clauses)
   ▼
SQLite (websites → comments → comment_aspects)
   │
   ▼
aggregation: score→stars, Bayesian smoothing, confidence, trust score ──► Streamlit app
```

## Setup and run

```bash
python -m venv venv && source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt                         # transformers/torch only needed for the Transformer engine
export PYTHONPATH=src                                   # Windows: set PYTHONPATH=src   (CLI modules only)

python -m opinion_mining.dataset_builder                # labelled clauses + 200 evaluation comments
python -m opinion_mining.aspect_ml                      # train aspect classifier (+ V1/V2 comparison)
python -m opinion_mining.spam_filter                    # build spam data, train + evaluate spam filter
python -m opinion_mining.seed_demo --reset              # demo websites and comments
streamlit run app/streamlit_app.py                      # the app (no PYTHONPATH needed)

python -m pytest -q                                     # tests
python -m opinion_mining.evaluation                     # full evaluation -> reports/evaluation_report.md
```

For the Transformer engine: `pip install torch --index-url https://download.pytorch.org/whl/cpu`
(first use downloads ~250 MB).

## Methods in brief

* **Clause splitting** (`but`, `however`, `,`, `and`, sentence ends) so each aspect gets its own sentiment;
  this is how *mixed* comments are handled.
* **Negation**: contractions are expanded ("didn't" → "did not"), negators are never removed, and phrase
  rules cover idioms ("not bad", "not on time", "no value for money").
* **Sarcasm**: positive opener + negative event in one clause ("Oh great, another late delivery") or a
  stock phrase → flipped to negative. A heuristic, not a model.
* **Stars**: `3 + 2·clip(score/0.6, −1, 1)`, then Bayesian smoothing toward 3.0 with 5 pseudo-reviews, so one
  comment cannot give 5.0 stars. **Confidence** = `n/(n+5)` → Low / Medium / High.
* **Trust score (0-100)**: importance- and confidence-weighted aspect stars; capped at 40 when genuineness is
  clearly bad (a site selling fakes cannot be "trusted" because it is cheap).
* **Spam**: TF-IDF (word + char) + 9 style features → Logistic Regression; threshold tuned for precision
  (blocking a real customer is worse than letting spam through). Spam is stored with weight 0.

## Results (`reports/evaluation_report.md`)

Evaluation set: 200 comments / 402 (aspect, sentiment) pairs, built from held-out clauses. VADER-only run.

| Pipeline | Aspect micro-F1 [95% CI] | Sentiment acc. (detected aspects) | End-to-end pair F1 |
|---|---|---|---|
| V1 keyword + VADER | 0.866 [0.843, 0.889] | 0.676 | 0.585 |
| V2 ML aspects + VADER (+ sarcasm) | 0.887 [0.866, 0.907] | 0.648 | 0.575 |
| V2 + Transformer | *run `python -m opinion_mining.evaluation` locally* | | |

Sentiment ablation on held-out clauses (accuracy): raw VADER 0.32 → + domain lexicon 0.48 → + rules 0.58.

**Reading these honestly**
* Aspect detection is good; **sentiment is the bottleneck** (~30 % of detected aspects are scored Neutral).
* V2 finds more aspects than V1, but the extra ones are often scored Neutral, so end-to-end F1 does not improve.
* The evaluation data is **synthetic** (exact labels, limited wording variety), so all numbers are optimistic,
  and the 200 comments reuse ~60 distinct clauses, so the bootstrap CIs are too narrow.

## Limitations

* No real-world labelled data; spam and evaluation sets are synthetic or author-written.
* Sarcasm is heuristic and clause-level (misses "Fantastic, only 3 weeks!" and flips some genuine praise).
* Clauses with an opinion but no aspect word ("Very disappointing.") are not attached to the previous aspect.
* No user accounts or rate limiting; SQLite suits a prototype, not heavy traffic.
* The Transformer path was not run in the authoring environment (no model download access).
